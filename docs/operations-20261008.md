# ChordLab 維運與還原

## 備份

`chordlab-backup.timer` 每天約 03:15 台灣時間啟動。快照位於 `/mnt/sdc/backups/chordlab-auto/<UTC 時間>/`：

- `chordlab.sqlite3`：SQLite 線上備份、完整性檢查，並複製到暫存目錄做還原演練；
- `jobs/`：歌曲與分析產物，次日快照對未變更檔案使用硬連結；
- `project/`：原始碼、測試、文件與鎖定檔；
- `private/`：權限 0600 的 `.env` 和 Google OAuth 設定。

備份目錄權限 0700，分析沙箱遮蔽 `/mnt/sdc`。不複製可重裝的 Python 環境、模型權重與本機二進位工具。每天的快照是同一台伺服器的第二顆磁碟，仍需另行規劃異地備份。快照不自動刪除；管理員應定期檢查容量。

檢查最新快照與排程：

```bash
systemctl --user list-timers chordlab-backup.timer
.venv/bin/python tools/backup_project.py --check
df -h /mnt/sdc
```

## 還原演練

在新目錄複製最新快照的 `project/`、`chordlab.sqlite3`、`jobs/`，確認 `private/` 不公開，然後依 README 安裝環境與模型。更新 `.env` 的 `CHORDLAB_JOBS_DIR`、OAuth 檔路徑，先在非公開埠啟動，確認 `/api/health`、登入及已完成歌曲的音訊與分析結果，再切換正式服務。不要直接覆蓋正在運作的資料庫或歌曲目錄。

正式回復時先停止 `chordlab.service`，再搬移或複製資料；保留原始目錄直到驗證通過。多個快照間以硬連結共用未變動檔案，不要修改快照內的歌曲。

## 準確度與發布門檻

`benchmarks/evaluation-20261008.json` 含 12 段真實木吉他回歸測試；可能與模型訓練資料重疊，且尚缺真實電吉他、Bass、完整樂團錄音，所以不能當獨立盲測。`tools/accuracy_gate.py` 要求四種來源、開發與回歸組各至少三段音訊、完整評估、無已知模型訓練重疊；音高／起音、延音、畫面 TAB、實際弦格、和弦時間與切換點不得明顯退步，回歸組至少一項要改善。門檻通過後還需人工試聽與核對譜面。

只有取得授權、與錄音對齊且同調弦／Capo 的人工標註，才能擴充這個對照集。現有資料不能證明和弦準確率已提高；因此任何新的分析變體仍須標示實驗性，不能只憑自我比對自動升成預設。

## 服務容量

正式服務目前固定單一 uvicorn 行程；工作佇列與混音請求去重都依賴行程內協調。`CHORDLAB_MAX_TOTAL_PENDING` 預設 24，可限制等待中的總工作數。若要擴展成多行程或多台伺服器，需先將工作領取、鎖及任務心跳搬到跨行程的持久化佇列；直接增加 uvicorn worker 數會造成重複處理。排隊中的分析可立即取消；執行中的分析在目前模型步驟結束後停止。服務重啟後會重新排隊，並重用檔案完整且版本相符的下載、音訊轉換、分軌、音符、和弦等階段產物；產物缺失或程式版本改變時重算。正在執行的單個模型無法即時中斷。
